# Moduly 개인정보처리방침

시행일: 2026년 8월 14일 (배포 전 검토용 초안)

> 이 문서는 현재 저장소의 Flutter 앱과 Supabase 기반 백엔드 구현에서 확인되는 처리 흐름을 설명하는 초안입니다. 법률 자문이 아니며, 실제 배포 전 운영자는 사업자 정보, 연락처, 보관기간, 수탁자·리전, 국외 이전과 삭제 절차를 사실에 맞게 보완하고 필요한 법률 검토를 진행해야 합니다.

## 1. 적용 범위

이 방침은 Moduly 모바일 앱(이하 “앱”)과 앱이 연결하는 Supabase 인증·데이터 저장 기능에 적용됩니다. 이 저장소에는 실제 운영자의 법적 명칭이나 연락처가 정해져 있지 않으므로 임의의 이름, 이메일, 전화번호 또는 지원 URL을 기재하지 않습니다.

## 2. 개인정보처리자 및 문의

개인정보처리자는 앱을 실제로 배포·운영하는 주체입니다. 열람·정정·삭제·처리정지 등의 요청을 받을 실제 연락처와 처리 절차는 운영자가 스토어 제출 전에 확정하여 이 문서와 스토어 고지에 반영해야 합니다.

## 3. 처리하는 정보

현재 구현에서 다음 정보가 처리될 수 있습니다.

- 계정·인증: 이메일 주소, Supabase Auth 사용자 식별자, 이메일 인증·비밀번호 재설정 상태, 로그인 세션 정보
- 프로필: 표시 이름, 선택적 아바타 URL, IANA 시간대
- 그룹·멤버십: 그룹 이름·시간대, 소유자·멤버 식별자, 역할, 가입·초대·활성/비활성 상태와 관련 시각
- 일정: 제목, 설명, 시작·종료 시각, 시간대, 종일 여부와 날짜 범위, 작성자와 버전 정보
- 초대·보안 기록: 초대 코드 해시, 만료·폐기·사용 횟수 메타데이터, 초대 참여 시도의 해시·시각·결과, 그룹·멤버십·초대·일정에 대한 최소 감사 메타데이터

초대 코드 원문은 저장하지 않고 생성 시 한 번 반환됩니다. 로그인 유지를 위해 인증 SDK가 관리하는 세션 정보가 기기에 저장될 수 있습니다. 저장소에서 확인되지 않는 연락처, 결제, 광고 식별자, 위치, 사진·파일 수집을 이 문서가 전제하지는 않습니다.

## 4. 처리 목적

- 계정 생성, 이메일 확인, 로그인·로그아웃, 비밀번호 재설정
- 그룹 생성·참여, 멤버 초대·관리, 그룹 구성원 간 일정 표시·동기화
- 시간대에 맞는 일정 표시와 종일 일정 입력
- 초대 코드의 만료·폐기·사용 한도, 중복 참여, 속도 제한 처리
- 권한 확인, 낙관적 잠금 충돌 처리, 보안·감사 추적, 장애·분쟁 대응

새 목적이나 선택적 기능을 추가할 때에는 실제 처리 여부와 고지를 다시 검토합니다.

## 5. 처리 방법과 접근 범위

앱은 Supabase Auth 및 데이터베이스를 사용해 인증과 동기화를 수행합니다. 공개 클라이언트에는 publishable(anon) 키만 사용하고, 데이터베이스의 행 수준 보안 정책(RLS)은 로그인한 사용자의 식별자와 활성 그룹 멤버십을 기준으로 접근을 제한하도록 설계되어 있습니다. 같은 그룹의 활성 구성원에게 그룹 운영에 필요한 프로필·멤버십·일정 정보가 표시될 수 있고, 그룹 소유자에게 초대·멤버 관리 정보가 표시될 수 있습니다.

데이터 전송의 보안 설정과 배포 리전은 실제 운영 환경을 기준으로 운영자가 확인해야 합니다.

## 6. 제3자 제공 및 처리위탁

현재 구현은 인증·데이터 저장·동기화를 위해 Supabase 서비스를 사용합니다. 실제 프로젝트의 호스팅 형태, 제공자 법인, 데이터 리전, 국외 이전 여부, 하위 처리자와 계약 내용은 배포 환경에 따라 달라질 수 있으므로 운영자가 확인한 사실만 최종 문서에 기재해야 합니다. 광고·판매 목적의 제3자 제공을 전제하지 않습니다. 법령상 의무, 이용자 요청 처리 또는 보안 대응에 필요한 공개가 있는 경우에는 적용 법령이 허용하는 범위에서 처리합니다.

## 7. 보유 및 파기

계정·프로필·그룹·멤버십·일정은 서비스 이용과 동기화에 필요한 동안 보유할 수 있습니다. 감사·보안 및 초대 참여 기록은 해당 목적, 분쟁 대응 또는 법령상 보존 의무에 필요한 범위에서 보관한 뒤 파기합니다.

앱의 계정 삭제 화면에서 확인 문구를 입력해 삭제를 요청할 수 있습니다. 요청은 로그인 세션의 사용자 토큰을 서버에서 다시 확인한 뒤 처리됩니다. 계정이 삭제되면 해당 이용자가 소유한 일정방과 그 일정방의 일정·멤버십·초대 코드가 함께 영구 삭제되고, 다른 일정방에서 해당 이용자가 만든 일정과 멤버십도 삭제됩니다. 보안·감사 기록은 관련 법령이나 보안 대응에 필요한 범위에서 남을 수 있으며, 삭제된 계정을 식별하지 않도록 작성자·일정방 식별자가 비워질 수 있습니다. 삭제가 완료되면 앱은 세션을 정리하며, 이 처리는 복구할 수 없습니다.

저장소에는 운영자의 구체적인 보관기간이나 자동 삭제 작업이 정해져 있지 않습니다. 실제 보관기간·파기 방법·감사 기록의 보존기간은 운영자가 배포 전에 확정하고 최종 문서에 반영해야 합니다.

## 8. 이용자의 권리와 행사 방법

이용자는 관련 법령이 정하는 범위에서 열람, 정정, 삭제, 처리정지 또는 동의 철회 등을 요청할 수 있습니다. 요청은 운영자가 최종 고지한 실제 연락처와 절차로 접수하며, 본인 확인과 다른 이용자의 권리 보호를 위해 필요한 범위의 확인을 요청할 수 있습니다.

그룹에 입력한 일정·프로필 정보는 그룹 구성원에게 공유될 수 있습니다. 다른 구성원 정보의 삭제를 요청할 때에는 그룹 소유자 또는 운영자의 권한 확인이 필요할 수 있습니다.

## 9. 안전성 확보 조치

앱과 백엔드는 인증 세션, RLS 정책, 그룹 멤버십 확인, 최소 권한 데이터베이스 권한, 초대 코드 해시 저장, 만료·사용 한도와 속도 제한, 버전 충돌 검사를 사용하도록 설계되어 있습니다. 운영자는 배포 환경의 TLS, 접근권한, 비밀 관리, 백업과 로그 보호를 별도로 점검해야 합니다. 이용자는 비밀번호와 초대 링크를 공유하지 않아야 합니다.

## 10. 정책 변경

처리 목적, 정보 범주, 보유기간 또는 권리 행사 방법이 바뀌면 변경 내용과 시행일을 앱 또는 스토어에서 알립니다. 앱 화면의 문서와 스토어에 연결한 정적 문서가 다르면 최신 시행 문서와 배포 공지를 확인해야 합니다.

## 11. 배포 전 확인

이 초안에는 운영자명·주소·연락처·보관기간·수탁자·국외 이전·삭제 절차를 임의로 만들지 않았습니다. 공개 전에 운영자는 해당 항목을 사실에 맞게 보완하고, 스토어의 개인정보처리방침 URL에는 실제로 호스팅한 HTTPS 문서만 등록해야 합니다.
